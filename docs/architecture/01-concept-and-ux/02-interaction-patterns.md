# 1.2. Базовые паттерны взаимодействия (Interaction Patterns) {#sec-02-interaction-patterns}

## 1.2.1. Двухфазный цикл стыковки и прилипания

Для обеспечения предсказуемости поведения окон перемещение и стыковка разделяются на две непрерывные фазы: **Фазу интерактивного предпросмотра (Preview Phase)** и **Фазу фиксации состояния (Commit Phase)**.

```text
[Захват заголовка указателем]
              |
              v
[Фаза 1: Свободное перемещение окна за указателем]
              |
              +---> Пересечение триггерной зоны границы/соседа?
              |         |
              |         +--[ДА]---> [Отображение контура SnapPreviewBox]
              |         |           (Окно продолжает следовать за курсором)
              |         |
              |         +--[НЕТ]--> [Очистка контура предпросмотра]
              |
              v
[Фаза 2: Отпускание кнопки указателя]
              |
              +---> Контур предпросмотра активен?
                        |
                        +--[ДА]---> [Фиксация геометрии по расчетной зоне]
                        |           (Плавный переход в тайловое состояние)
                        |
                        +--[НЕТ]--> [Фиксация текущих плавающих координат]
```

1. **Фаза интерактивного предпросмотра:**
   * Пока удерживается кнопка манипулятора, окно перемещается синхронно с указателем. Внезапные скачкообразные телепортации окна запрещены.
   * При входе курсора в пороговую зону прилипания на холсте отображается полупрозрачный визуальный маркер расчетных габаритов будущей стыковки.
   * Пользователь наглядно видит, какую область займет контейнер, сохраняя контроль над текущим перемещением. Выход курсора из триггерной зоны плавно деактивирует маркер.

2. **Фаза фиксации состояния:**
   * Переход окна в пристыкованное (тайловое) состояние происходит исключительно в момент снятия удерживающего жеста.
   * Если маркер предпросмотра активен, окно анимированно принимает расчетные координаты и пропорции целевой зоны. Если маркер отсутствует, окно остается в текущих координатах с сохранением плавающего статуса.

## 1.2.2. Режим сольного фокуса (Solo / Focus Mode)

В аналитических и комплексных рабочих средах востребован сценарий временного развертывания одной конкретной панели на всю площадь холста с последующим мгновенным возвратом к исходной многооконной компоновке.

Механика режима сольного фокуса:

1. **Инициирование:** Активируется двойным кликом по свободной зоне заголовка окна или выбором соответствующего элемента управления.

2. **Изоляция:** Целевой контейнер плавно развертывается на 100% полезной площади холста. Все остальные контейнеры временно переводятся в пассивный фоновый режим без деструкции их внутреннего состояния.

3. **Сохранение контекста сетки:** Геометрические параметры, пропорции общих швов и координаты всех скрытых окон сохраняются в неизменном виде в графе состояния.

4. **Возврат:** Повторный вызов действия снимает режим изоляции: целевое окно возвращается к исходным координатам, а окружающая сетка восстанавливается в исходной конфигурации.

## 1.2.3. Инварианты плавности взаимодействия

Для предотвращения утомляемости оператора и снижения визуального шума архитектура фиксирует следующие эргономические инварианты:

* **Инвариант отсутствия микроскачков:** Любое изменение линейных размеров или координат окна при стыковке сопровождается непрерывной интерполяцией с длительностью не более 100–120 миллисекунд. Мгновенные неанимированные трансформации допускаются только при аппаратной инициализации холста.
* **Инвариант изоляции зон рендеринга:** Перемещение одного окна в иерархии слоев не должно приводить к инвалидации графического контекста неподвижных соседних окон. Каждый контейнер функционирует в автономном графическом слое.
* **Инвариант устойчивости геометрии:** Никакое внешнее действие не может уменьшить размер контейнера ниже его минимальных допустимых физических пределов.
