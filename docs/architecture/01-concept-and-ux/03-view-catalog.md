# 1.3. Каталог и обнаружение представлений (View Catalog) {#sec-03-view-catalog}

## 1.3.1. Реестр прикладных компонентов и статусы видимости

Каталог представлений (View Catalog) представляет собой архитектурный реестр доступных прикладных панелей системы. Каталог исключает проблему «потерянных окон», когда закрытый пользователем компонент невозможно вернуть без перезапуска всего приложения.

Каждый зарегистрированный в каталоге компонент описывается статической декларацией и динамическим состоянием:

```text
Декларация представления:
  - Уникальный строковый идентификатор типа (Component Type ID)
  - Отображаемое наименование по умолчанию
  - Базовая пиктограмма
  - Ограничения габаритов (min/max ширина и высота)
  - Стратегия инстанцирования (Singleton или Multi-Instance)

Динамический статус экземпляра:
  - ACTIVE    : Контейнер открыт на холсте и находится в фокусе
  - INACTIVE  : Контейнер открыт на холсте под другими окнами
  - MINIMIZED : Контейнер свернут в панель быстрого доступа
  - CLOSED    : Компонент отсутствует на холсте
```

Стратегии инстанцирования компонентов:

1. **Сингулярные компоненты (Singleton Views):** В пределах одного рабочего пространства может существовать строго один экземпляр панели (например, главное окно параметров или глобальный системный журнал). Попытка открыть сингулярный компонент повторно не создает новое окно, а плавно переводит фокус на уже существующий контейнер.

2. **Множественные компоненты (Multi-Instance Views):** Допускают создание произвольного количества независимых копий на холсте (например, инспекторы отдельных сущностей, детальные графики, сравнительные терминалы). Каждая копия наделяется уникальным идентификатором экземпляра при сохранении общего типа.

## 1.3.2. Восстановление и инстанцирование окон

Каталог представлений предоставляет унифицированный интерфейс обнаружения компонентов:

1. **Отображение доступности:** Пользователю доступен интерфейс реестра (в виде выпадающего меню панели быстрого доступа или специализированного диалога палитры компонентов), где наглядно отображаются все прикладные панели с индикацией их текущего статуса.
2. **Восстановление закрытых панелей:** Если требуемый компонент находится в статусе `CLOSED`, клик по его элементу в каталоге мгновенно инстанцирует новый контейнер на свободном участке холста либо добавляет его вкладкой в активное окно.
3. **Фокусировка скрытых панелей:** Если запрашиваемый компонент уже находится на холсте, но скрыт под другими окнами или минимизирован, выбор в каталоге автоматически разворачивает его и переносит на верхний уровень порядка наложения (Z-Index).
