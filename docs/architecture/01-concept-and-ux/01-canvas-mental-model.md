# 1.1. Ментальная модель рабочего пространства {#sec-01-canvas-mental-model}

## 1.1.1. Концепция композитного холста

В основе системы лежит парадигма **композитного рабочего холста (In-App Composite Canvas)**. В отличие от платформ виртуализации или оконных сред операционных систем, композитный холст проектируется как специализированный компонент прикладного интерфейса, функционирующий внутри выделенного видового экрана.

Холст представляет собой двумерную координатную плоскость фиксированного или динамического размера, в границах которой размещаются пространственные контейнеры (окна). Назначение холста ограничивается тремя фундаментальными задачами:

1. Управление пространственным размещением, границами и взаимным перекрытием контейнеров.
2. Трансляция и декомпозиция событий манипулятора (указателя, мыши, жестов) в пространственные трансформации (смещение, деформация границ, стыковка).
3. Обеспечение изолированной проекции пользовательского содержимого внутрь выделенных контейнеров.

Холст полностью абстрагирован от семантики размещаемого содержимого. Контейнер оперирует исключительно геометрическими и метаинформационными параметрами (габариты, заголовок, пиктограмма, уникальный идентификатор), делегируя построение визуального дерева внешней фабрике представлений.

## 1.1.2. Принцип слабой связности: контейнер и содержимое

Архитектура системы строится на строгом разделении понятий **Оконного контейнера** и **Прикладного представления**:

```text
+-------------------------------------------------------------------+
|                        ПРИКЛАДНОЙ ХОСТ                            |
|  - Бизнес-логика, контроллеры потоков, модели данных             |
+-------------------------------------------------------------------+
                                  |
                                  v
+-------------------------------------------------------------------+
|               ОКОННЫЙ МЕНЕДЖЕР (DESKTOP WORKSPACE)                |
|  +-------------------------------------------------------------+  |
|  |             КОНТЕЙНЕР ОКНА (ГЕОМЕТРИЯ И СТЕК ТАБОВ)          |  |
|  |  - Координаты (x, y), Размеры (w, h), Z-Index               |  |
|  |  - Заголовок, Чипы вкладок, Органы управления               |  |
|  |  - Физика прилипания, Матрица швов, Сохранение сессии        |  |
|  +-------------------------------------------------------------+  |
+-------------------------------------------------------------------+
                                  |
               (Делегирование отрисовки содержимого)
                                  v
+-------------------------------------------------------------------+
|                     ПРИКЛАДНОЕ ПРЕДСТАВЛЕНИЕ                      |
|  (График, Редактор, Консоль, Инспектор данных, Видеопоток)        |
+-------------------------------------------------------------------+
```

Контейнер окна берет на себя рутинные аспекты интерфейса:
- Отрисовку структурной рамки с индикацией активного фокуса.
- Предоставление интерактивного заголовка для перемещения и операций над окном.
- Организацию множественных вкладок и переключение между ними.
- Обработку восьмивекторного изменения габаритов окна.

Прикладное представление изолировано от оконного менеджера. Оно не производит самостоятельных расчетов своего положения на экране, не обрабатывает системные границы и взаимодействует с внешней системой исключительно через передаваемые параметры и контекстные метаданные.

## 1.1.3. Принцип ненавязчивости (Non-Intrusiveness)

Оконный менеджер проектируется по принципу пассивного интерфейсного сервиса. Система исключает поведение, способное нарушить нормальное функционирование прикладных компонентов или механизмов ввода:

1. **Исключение монопольного перехвата клавиатуры:** Система не регистрирует глобальных перехватчиков нажатий клавиш клавиатуры на уровне корневого холста. Ввод с физической клавиатуры беспрепятственно поступает напрямую в активный сфокусированный компонент (текстовые редакторы, терминалы, специализированные поля ввода).
2. **Изоляция указателя (Pointer Isolation):** События манипулятора обрабатываются оконным менеджером строго в пределах интерактивных управляющих зон (полоса заголовка, ручки изменения размера шириной в несколько пикселей по периметру). Вся внутренняя область контейнера полностью прозрачна для событий мыши и передает их дочернему представлению без модификации.
3. **Отсутствие псевдосистемных метафор:** В интерфейсе исключаются фиктивные системные часы, календари, псевдолаунчеры операционных систем и вспомогательные панели, дублирующие штатные функции рабочей среды пользователя.
