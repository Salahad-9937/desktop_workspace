# 6.2. Паттерн фабрики представлений (View Factory) {#sec-02-view-factory-pattern}

## 6.2.1. Контракт связывания метаданных с компонентами

Для сохранения абсолютной слабой связности между оконным менеджером и прикладными панелями применяется паттерн **Фабрики представлений (View Factory / Content Provider)**.

Контракт фабрики определяется чистой функциональной сигнатурой:

```text
Входные параметры:
  - context      : Контекст графического дерева платформы
  - windowState  : Снимок геометрического состояния несущего окна
  - tabMeta      : Метаданные активной вкладки (id, typeId, payload)

Выходное значение:
  - ViewInstance : Экземпляр визуального прикладного компонента
```

Схема маршрутизации фабрики:

```text
[Оконный фрейм запрашивает отрисовку Tab(typeId: "telemetry_chart")]
                                 |
                                 v
+-----------------------------------------------------------------+
|                   ФАБРИКА ПРЕДСТАВЛЕНИЙ (ХОСТ)                  |
|                                                                 |
|   match (tabMeta.typeId) {                                      |
|       "telemetry_chart" => return TelemetryChart(tab.payload),  |
|       "code_editor"     => return CodeEditor(tab.payload),      |
|       "3d_viewport"     => return Viewport3D(tab.payload),      |
|       _                 => return FallbackPlaceholder(tab),     |
|   }                                                             |
+-----------------------------------------------------------------+
                                 |
                                 v
[Контейнер монтирует полученный компонент в retention-стек]
```

---

## 6.2.2. Изоляция зависимостей и бизнес-логики

Преимущества использования фабричного контракта:

1. **Нулевая связанность:** Библиотека оконного менеджера не импортирует прикладные пакеты, модели данных предметной области или сетевые контроллеры хоста.
2. **Динамическая подмена:** Хостовое приложение способно подменять реализации представлений в зависимости от окружения (например, отдавать легковесную заглушку в тестах или полноразмерный компонент в боевом режиме).
3. **Безопасная обработка неизвестных типов:** При попытке открыть вкладку с устаревшим или неизвестным `typeId` фабрика возвращает нейтральный плейсхолдер с сообщением об отсутствии модуля, предотвращая аварийный сбой всей системы.
