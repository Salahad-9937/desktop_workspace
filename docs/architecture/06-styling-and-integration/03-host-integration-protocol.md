# 6.3. Протокол интеграции в хостовое приложение {#sec-03-host-integration-protocol}

## 6.3.1. Жизненный цикл инициализации рабочего пространства

Интеграция рабочего пространства в хостовое приложение проходит через последовательные этапы инициализации:

```text
+-------------------------------------------------------------+
| 1. ОПРЕДЕЛЕНИЕ КАТАЛОГА ПРЕДСТАВЛЕНИЙ                       |
|    - Регистрация доступных типов панелей и их ограничений   |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| 2. КОНФИГУРАЦИЯ СТАРТОВОГО МАКЕТА                           |
|    - Выбор декларативного пресета (Сетка 2x2, Сплит, Соло)  |
|    - Либо загрузка снимка последней сессии из хранилища      |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| 3. МОНТИРОВАНИЕ ХОЛСТА (WORKSPACE CANVAS)                   |
|    - Передача темы оформления (ThemeData)                   |
|    - Передача фабрики представлений (ContentBuilder)        |
|    - Настройка слотов дока (Leading / Trailing)             |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| 4. РАБОЧИЙ ЦИКЛ: ДВУНАПРАВЛЕННЫЙ ОБМЕН СОБЫТИЯМИ            |
|    - Хост вызывает команды контроллера                      |
|    - Менеджер уведомляет хост об изменениях через колбэки   |
+-------------------------------------------------------------+
```

---

## 6.3.2. Протокол двунаправленного обмена событиями

Взаимодействие между хостом и оконным менеджером осуществляется через четкий интерфейсный протокол:

1. **Команды хоста к менеджеру (Downstream Commands):**
   * `openView(typeId, payload)`: запрос на открытие новой панели на свободном участке холста или вкладкой.
   * `activateProfile(profileId)`: программное переключение раскладки на заданный профиль.
   * `toggleSoloMode(windowId)`: развертывание целевой панели в режим монопольного фокуса.
   * `resetLayout()`: сброс текущей геометрии к исходному заводскому состоянию.

2. **События менеджера к хосту (Upstream Notifications):**
   * `onLayoutMutated(snapshot)`: уведомление об изменении взаимного расположения окон (триггер для автосохранения сессии).
   * `onWindowFocused(windowId, activeTab)`: уведомление о смене активного фокуса (хост может синхронизировать глобальное контекстное меню или строку статуса).
   * `onTabClosed(tabId, payload)`: уведомление о закрытии вкладки (хост может освободить связанные фоновые ресурсы, отписаться от сетевых сокетов).

Такой протокол обеспечивает полный контроль хоста над поведением рабочего пространства, гарантируя при этом автономность и чистоту архитектуры оконного менеджера.
