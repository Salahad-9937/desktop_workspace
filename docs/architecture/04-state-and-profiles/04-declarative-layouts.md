# 4.4. Декларативная спецификация начальных макетов {#sec-04-declarative-layouts}

## 4.4.1. Декларативные структуры описания макетов

Для инициализации стартовых раскладок рабочего пространства архитектура предоставляет декларативные схемы описания геометрии. Разработчик прикладного приложения описывает начальную конфигурацию сетки непосредственно в коде интерфейса через типизированные структуры:

```text
Декларативные схемы компоновки:

1. Сетка 2x2 (GridLayout):
   - Верхний левый слот   : [ Вкладка А, Вкладка Б ]
   - Верхний правый слот  : [ Вкладка В ]
   - Нижний левый слот    : [ Вкладка Г ]
   - Нижний правый слот   : [ Вкладка Д ]

2. Пропорциональный сплит (SplitLayout):
   - Направление : Горизонтальное / Вертикальное
   - Пропорция   : Доля ведущей зоны (например, 0.6 / 0.4)
   - Ведущая зона: Стек вкладок
   - Ведомая зона: Стек вкладок

3. Свободное размещение (FreePlacementLayout):
   - Список абсолютных или относительных координат [ WindowPlacement(...) ]
```

---

## 4.4.2. Инициализация без внешних файлов конфигурации

Декларативный подход исключает необходимость создания и парсинга внешних текстовых файлов при старте приложения:

* Все макеты валидируются компилятором на этапе сборки проекта.
* Ошибки в именах вкладок или неверные пропорции выявляются статическим анализатором кода.
* При первом запуске приложение мгновенно разворачивает заданную разработчиком эталонную сетку, после чего управление компоновкой передается пользователю.
