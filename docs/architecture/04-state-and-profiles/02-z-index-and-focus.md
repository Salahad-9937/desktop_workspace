# 4.2. Порядок слоев (Z-Index) и модель фокуса {#sec-02-z-index-and-focus}

## 4.2.1. Алгоритм всплытия активного окна (Bring to Front)

Порядок наложения окон в двумерном пространстве холста задается их физическим порядком в списке `windows` снимка состояния. Окно с большим индексом отображается поверх окон с меньшими индексами.

Алгоритм передачи фокуса и всплытия при касании окна $W_{target}$:

1. Контроллер производит поиск индекса целевого окна в списке.

2. Окно $W_{target}$ извлекается из текущей позиции массива и вставляется в самый конец списка (позиция $N - 1$).

3. Идентификатор `focusedWindowId` обновляется значением $W_{target}.id$.

4. Все компоненты холста получают обновленный список: целевое окно визуально оказывается на самом переднем плане, а его заголовок и рамка окрашиваются в активные акцентные цвета.

## 4.2.2. Приоритетный слой закрепления поверх всех окон (Always on Top)

В ряде сценариев требуется удерживать определенную панель (например, миниатюрный видеомонитор или панель системных индикаторов) видимой независимо от того, какие окна перемещаются или активируются на холсте.

Для реализации этого поведения массив окон при рендеринге виртуально разделяется на два изолированных яруса:

```text
Стек отрисовки холста:

ЯРУС 2: ЗАКРЕПЛЕННЫЕ ОКНА (isPinnedOnTop = true)
  [ Окно P1 (верхний приоритет) ]
  [ Окно P0 ]
==============================================================
ЯРУС 1: ОБЫЧНЫЕ ОКНА (isPinnedOnTop = false)
  [ Окно W2 (активное обычное окно) ]
  [ Окно W1 ]
  [ Окно W0 (фоновое окно) ]
==============================================================
ЯРУС 0: ФОНОВЫЙ ХОЛСТ
```

Правила взаимодействия ярусов:

1. Любое окно из Яруса 2 гарантированно отрисовывается поверх любого окна из Яруса 1.

2. Клик по обычному окну из Яруса 1 перемещает его на вершину Яруса 1, но оно физически не может перекрыть закрепленные окна из Яруса 2.

3. Внутри самого Яруса 2 действует стандартный порядок всплытия: последнее активированное закрепленное окно оказывается выше остальных закрепленных окон.
