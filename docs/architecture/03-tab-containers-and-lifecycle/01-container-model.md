# 3.1. Модель вкладочного контейнера {#sec-01-container-model}

## 3.1.1. Структура метаданных вкладки

Вкладка представляет собой независимую спецификацию прикладного представления, размещенного внутри оконного фрейма. Каждая вкладка инкапсулирует исчерпывающий набор метаданных, необходимых для ее идентификации, отрисовки в полосе заголовка и управления отображением:

```text
Структура метаданных вкладки (Tab Entity):
  - id           : Уникальный строковый идентификатор экземпляра
  - typeId       : Идентификатор типа представления (сопоставляется с фабрикой)
  - title        : Отображаемый текстовый заголовок вкладки
  - icon         : Символический идентификатор пиктограммы
  - accentColor  : Цветовой токен модальности (опционально)
  - keepAlive    : Директива удержания внутреннего состояния в памяти
  - constraints  : Индивидуальные геометрические ограничения окна
  - payload      : Сериализуемый контейнер прикладных параметров
```

Роль компонентов структуры:

* **Идентификатор экземпляра (`id`):** Обеспечивает точечную адресацию вкладки при операциях переноса, фокусировки и закрытия независимо от ее позиции в стеке.

* **Идентификатор типа (`typeId`):** Передается во внешнюю фабрику представлений для инстанцирования целевого прикладного компонента.

* **Полезная нагрузка (`payload`):** Словарь произвольных типизированных параметров, определяющий начальное состояние компонента (например, путь к открытому файлу, идентификатор сущности для инспекции или режим отображения графика).

## 3.1.2. Иерархия и разрешение размерных ограничений

Контейнер окна обязан учитывать геометрические требования размещенных в нем вкладок. Разные прикладные панели предъявляют различные требования к физическому пространству (например, сложный трехмерный вьюпорт требует минимальной площади $600 \times 400$ пикселей, тогда как компактный текстовый лог способен функционировать при $250 \times 150$).

Разрешение действующих ограничений окна $C_{effective} = \langle W_{min}, \ W_{max}, \ H_{min}, \ H_{max} \rangle$ подчиняется строгой иерархии:

```text
[Глобальные ограничения холста (WorkspaceConfig)]
                      |
                      v (наследуются по умолчанию)
[Ограничения оконного фрейма (Window Constraints)]
                      |
                      v (переопределяются активной вкладкой)
[Ограничения текущей вкладки (Active Tab Constraints)]
```

Математическое правило вычисления эффективных ограничений для контейнера со стеком вкладок $\mathcal{T} = [T_0, T_1, \dots, T_k]$ при активном индексе $a$:

$$W_{min\_effective} = \max\left( W_{min\_global}, \quad W_{min}(T_a) \right)$$

$$H_{min\_effective} = \max\left( H_{min\_global}, \quad H_{min}(T_a) \right)$$

При переключении активной вкладки с $T_i$ на $T_j$:

1. Если текущие ширина $w$ или высота $h$ окна оказываются меньше новых минимальных требований $W_{min}(T_j)$ или $H_{min}(T_j)$, окно плавно увеличивает свои габариты до нового нижнего порога.

2. Новые координаты левого верхнего угла $(x, y)$ повторно проверяются алгоритмом удержания в границах экрана для исключения выхода разросшегося окна за пределы видимости.
