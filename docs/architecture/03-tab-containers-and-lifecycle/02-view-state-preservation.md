# 3.2. Сохранение состояния представлений (State Preservation) {#sec-02-view-state-preservation}

## 3.2.1. Проблема деструкции состояния в динамических деревьях

В стандартных реализациях переключения интерфейсов неактивное представление удаляется из визуального дерева, а новое монтируется на его место. В сложных настольных приложениях такой подход приводит к критическим нарушениям пользовательского опыта:

* Сброс позиций скролла в длинных аналитических таблицах и списках.
* Уничтожение не зафиксированного текстового ввода в поисковых строках и редакторах.
* Разрыв и повторная инициализация тяжелых графических контекстов (аппаратные 3D-растеризаторы, WebGL, векторные сцены).
* Потеря фокуса элементов ввода и непреднамеренный триггер сетевых запросов инициализации.

Оконный менеджер обязан изолировать **пространственное переключение видимости** от **жизненного цикла экземпляра представления**.

## 3.2.2. Архитектура удержания неактивных представлений

Для решения проблемы деструкции контейнер окна реализует многослойную архитектуру удержания экземпляров (View Instance Retention):

```text
+-------------------------------------------------------------+
|              ОКОННЫЙ КОНТЕЙНЕР (WINDOW FRAME)               |
|                                                             |
|  +-------------------------------------------------------+  |
|  |   [ Таб 1: График ]  [ Таб 2: Редактор* ]  [ Таб 3 ]  |  |
|  +-------------------------------------------------------+  |
|  |                                                       |  |
|  |  МНОГОСЛОЙНЫЙ СТЕК ПРЕДСТАВЛЕНИЙ (RETENTION STACK)    |  |
|  |                                                       |  |
|  |  Слой 0 (Таб 1): [График]                             |  |
|  |  - Статус: Скрыт (Offstage/Hidden)                    |  |
|  |  - Состояние: Удерживается в памяти, контекст жив    |  |
|  |                                                       |  |
|  |  Слой 1 (Таб 2): [Редактор]                           |  |
|  |  - Статус: АКТИВЕН (Отрисовывается, принимает ввод)  |  |
|  |  - Состояние: Живой фокус, активный курсор            |  |
|  |                                                       |  |
|  |  Слой 2 (Таб 3): [Инспектор]                          |  |
|  |  - Статус: Скрыт (Offstage/Hidden)                    |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

Принципы функционирования удерживающего стека:

1. **Удержание через директиву `keepAlive`:** Если в метаданных вкладки флаг `keepAlive = true`, при смене активного индекса неактивное представление не демонтируется, а переводится в пассивный графический слой с отключением расходования ресурсов отрисовки.

2. **Изоляция событий ввода:** Скрытые слои стека полностью отключаются от дерева событий указателя (`hitTestBehavior = none`), предотвращая случайную активацию кнопок или полей ввода на невидимых вкладках.

3. **Мгновенное переключение:** Возврат к ранее открытой вкладке происходит за нулевое время (Zero Latency Switch), так как подсистеме отрисовки требуется лишь активировать готовый визуальный слой без повторного вызова фабрики представлений.
